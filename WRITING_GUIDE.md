# Writing Guide — Matheus Theodoro

This guide captures the voice, structural patterns, and editorial rules for this blog. It exists to make edits consistent — especially when AI assists with writing.

## Voice

- **Short declarative sentences.** Lead with the claim. "The security frontier moved." Not "The security landscape has undergone a significant shift."
- **No hedging.** Don't say "it may be worth noting that" or "it is important to consider." Cut every sentence that starts with "It is X that." Just say the thing.
- **Bold statements, no apology.** Do not preface claims with "this is not meant to be definitive" or "the author believes." If you're unsure, don't write it. If you're sure, state it.
- **No "It's not X, but Y" structure.** Replace "The limitation is not that these concepts are wrong. The limitation is that they are incomplete" with "These concepts are right but incomplete."
- **No defensive framing.** No "this article makes a literature-grounded argument, not an empirical claim." If it's a position paper, own it.
- **No comma after "But."** "But when prototyping is cheap" not "But, when prototyping is cheap."
- **No "quietly" + verb.** No "quietly revolutionizes" or "quietly changes." Nothing quiet about good writing.
- **No double spaces between lines.** Single space after periods only.

## Sentence Patterns to Avoid

| Avoid | Use Instead |
|-------|-------------|
| "It is worth noting that X" | "X." |
| "It is important to recognize that X" | "X." |
| "This raises an important question" | Ask the question directly. |
| "not because... but because..." | State the reason directly. |
| "The good news... The bad news..." | State both as facts, not news. |
| "This tells the real story of..." | Let the evidence speak. |
| "I'll illustrate this through..." | Just give the example. |
| "But, that raises the question..." | "But that misses the point: question here." |
| "demand attention" / "deserve attention" | Nothing demands attention; make it interesting. |
| "For anyone building/attacking/defending X" | Write for the reader doing that, don't announce it. |
| "In fact," | Usually removable. |
| "Certainly, X" | Drop "Certainly." |
| "This is a paradox" | Probably not actually a paradox. |
| "First... Second... Third..." as paragraph openers | Use lists or avoid enumeration. |

## Structural Rules

- **One idea per post.** No surveys. No "four pillars." Pick one concept, go deep.
- **Open with the claim.** First paragraph states the thesis. No scene-setting, no throat-clearing.
- **No "Introduction" section.** Just start. Section headers like "## 1. Introduction" are for papers, not blog posts.
- **Use tables and lists** when they clarify. Don't bury data in paragraphs.
- **ASCII diagrams** are good, but only when they add something text cannot.
- **End with a forward-looking claim or a concrete insight.** Not a summary.
- **If you cite a paper, say what it actually found.** Don't drop citations as authority tokens.

## Image / Asset Rules

- Every image must be an actual image URL (png, jpg, svg, webp). No linking to HTML pages.
- For arXiv images, use the `https://arxiv.org/html/<id>/<filename>` pattern (e.g. the HTML rendering path).
- For SVG diagrams from GitHub, use `https://raw.githubusercontent.com/` URLs.
- Alt text describes what the image shows, not where it's from.

## Checklist for Review

- [ ] No "it is worth noting" / "it is important to"
- [ ] No "it's not X, but Y" constructions
- [ ] No "quietly" + verb
- [ ] No double spaces
- [ ] No comma after "But" (unless followed by a clause, not just a phrase)
- [ ] No defensive hedging ("may", "usually", "generally", "tends to")
- [ ] No "in fact" / "certainly" / "indeed" as sentence starters
- [ ] First paragraph states the thesis
- [ ] Every image URL points to an image file (not an HTML page)
- [ ] Every reference says what the paper found, not just that it exists
- [ ] No section titled "Introduction" (just start the content)
